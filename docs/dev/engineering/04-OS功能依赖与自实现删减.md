# 04 — OS 功能依赖清单：用了什么、如何参考 OS 删减成自实现

> **定位**：03 号文档盘点「我们替 OS 做了什么」；本文是反方向——
> **loomos 现在用了 OS 的哪些功能**，逐项列出，并给出
> **以 OS（Linux/POSIX）语义为规格书、删减成 loomos 自实现**的最小形态。
>
> **纪律**：本文只记录，不改代码。与 ADR-001（近期以 Linux 为宿主内核）不冲突——
> 这是**依赖面地图**：宿主阶段它是接口清单，原生阶段它是内核需求规格。
> 判据延续 architecture/09 §I：Linux 不满足才自研，本文负责把"自研要做什么"说清楚。

---

## 1. 依赖总表（现状实测：grep 全仓）

| 类 | OS 能力 | 落到的机制 | 消费点 | 自实现现状 |
|---|---|---|---|---|
| 内存 | 匿名内存分配 | brk/mmap（经 std 分配器） | 全部 Vec/Box | ❌ 纯依赖 |
| 内存 | 内核同步原语 | **futex**（std Mutex/RwLock/Condvar 底下） | 14 个文件的 std::sync | ❌ 纯依赖 |
| 并发 | 内核线程 | clone(THREAD) | thread::spawn ×4（HTTP 服务/采集线程） | ❌ 纯依赖 |
| 时间 | 单调钟 | clock_gettime(MONOTONIC) | Instant ×12（超时/RTF/耗时） | ❌ 纯依赖 |
| 时间 | 墙钟 | clock_gettime(REALTIME) | SystemTime ×6（事件戳/stale 判定） | ❌ 纯依赖 |
| 文件 | 读/写/追加 | open/read/write/close | fs::read/write ×11、OpenOptions ×2 | ❌ 纯依赖 |
| 文件 | **原子替换** | rename | fs::rename ×1（JsonFileProvider 持久化） | ❌ 纯依赖（崩溃安全的关键，唯一一处） |
| 文件 | 目录创建 | mkdir | fs::create_dir ×6 | ❌ 纯依赖 |
| 网络 | TCP (loopback) | socket/bind/listen/accept | TcpListener ×4（控制台 10900 / mock 板端） | ❌ 纯依赖 |
| 网络 | TCP 收发+超时 | read/write/setsockopt | TcpStream ×5、set_read_timeout ×1 | ❌ 纯依赖 |
| 进程 | 子进程探针 | fork/exec | Command::new ×1（cli 读 rustc 版本） | ❌ 纯依赖（仅报告用，可删） |
| 环境 | 参数/环境变量 | main argv/environ | env::args ×2 | ❌ 纯依赖 |
| 睡眠 | 定时等待 | clock_nanosleep | thread::sleep ×3 | ❌ 纯依赖 |
| 设备 | （未来）udmabuf/VPU/NPU 节点 | mmap+ioctl+sysfs | 尚未接入（Pipeline 模式无设备） | ⏳ 板上阶段 |
| 服务 | systemd 单元（旧板） | 单元文件+signal | 旧系统部署形态；loomosd 单进程未用 | ✅ **Supervisor 已是自实现雏形** |

**汇总**：真正 touch 到的 syscall 族 **≤ 15 个**
（mmap/brk、futex、clone、clock_gettime×2、open/read/write/close、rename、mkdir、
socket/bind/listen/accept/setsockopt、nanosleep、environ）。
**这是一个好消息**：自实现内核的 syscall 面可以做得非常小。

## 2. 逐项删减方案（参考 OS 语义 → loomos 自实现最小形态）

> 「参考 OS」= 把 Linux/POSIX 语义当**规格书**抄行为、不抄实现；
> 每项都先问：loomos 的语义真的需要 Linux 的全部吗？

### 2.1 线程 + 调度 → loomos 线程 + 两级调度器
- **OS 提供**：CFS 全公平调度、NUMA、cgroup 分组、优先级 1-99、DEADLINE。
- **loomos 实际用**：4 个 `thread::spawn`（HTTP 接收、录制线程）+ 未来 ExecutionContext.affinity。
- **自实现最小形态**：静态优先级 + 时间片轮转 + **DEADLINE 子集**（runtime/period/deadline
  三参数准入，loomos `CpuBudget` 已定义同一语义）；核亲和 = 运行队列位图（`CoreSet` 已有）。
- **砍掉**：公平份额、负载均衡、NUMA、cgroup 层级、nice 数值空间。
- **难点**：厂商 NPU 阻塞调用的优先级反转（保底：Owner 单队列已规避）。

### 2.2 futex 同步 → loomos 等待队列 + 快路径用户态 CAS
- **OS 提供**：futex(WAIT/WAKE/REQUEUE_PI…) 全家族。
- **loomos 实际用**：Mutex/RwLock/Condvar（短临界区，无跨进程）。
- **自实现最小形态**：参考 futex 语义的**双阶段锁**——用户态 CAS 快路径 +
  内核等待队列慢路径；只需要 WAIT/WAKE 两个操作。
- **砍掉**：PI 变体、跨进程 futex、robust list、futex 复合操作。
- **难点**：几乎无（loomos 同步场景简单，无跨进程锁）。

### 2.3 墙钟+单调钟 → loomos 两个计数器
- **OS 提供**：多时钟源、NTP 校正接口、高精度定时器层级。
- **loomos 实际用**：单调（超时/耗时）+ 墙钟（事件戳、stale 判定）；**无定时器唤醒依赖**
  （sleep ×3 是低频）。
- **自实现最小形态**：单调计数器（PL/SoC 计时器寄存器）+ 墙钟（RTC 或手动校准）；
  语义规格照抄 POSIX「单调不回退」「墙钟可跳变，因此 stale 判定必须用单调钟」。
- **砍掉**：动态时钟源、tickless 休眠细节、NTP 内核接口。
- **风险记录**：EventLog 的 wall_time_ms 可跳变——跨事件排序不能依赖它
  （旧系统 events.py 的 monotonic_ns 字段就是为此，**保留该纪律**）。

### 2.4 文件系统 → loomos 追加日志 + 扁平 namespace（**已有雏形**）
- **OS 提供**：ext4 整套（目录树、页缓存、日志、配额、属性）。
- **loomos 实际用**：JSONL 追加（EventLog）+ **一处** tmp+rename 原子替换（JsonFileProvider）
  + create_dir。**没有随机读写、没有目录遍历、没有大文件**。
- **自实现最小形态**：
  - EventLog → 追加式日志区（seq 已经内建，天然映射）；
  - 配置持久化 → **ConfigService 的扁平 NamespacePath 就是目录树的删减形态**
    （规范化/拒绝 `..` 那套校验，等于一个极简路径解析器）；
  - 原子替换语义 → 「写副本 + 提交指针」两步（对象存储式），rename 原子性由提交指针的单写者保证。
- **砍掉**：目录层级、硬链接、权限位（capability 已覆盖）、页缓存策略、动态扩容、FS 错误码的 90%。
- **难点**：断电一致性——但 Desired/Applied 语义已经容忍"部分持久化后重放"。

### 2.5 TCP loopback → loomos 消息端点（**HTTP 解析已自实现**）
- **OS 提供**：完整 TCP/IP 栈、拥塞控制、socket 缓冲、DNS。
- **loomos 实际用**：**127.0.0.1 回环**上的 HTTP/1.1（自写解析器 mini_http，无 TLS、无 DNS）。
- **自实现最小形态**：回环 TCP 在原生形态下**根本不需要网络栈**——控制台/组件间通信
  直接映射为 capability 保护的**消息端点**（loomosd 的 `/handle_text` 就是消息语义）；
  HTTP 解析器（mini_http）原样保留作线上协议层。
- **砍掉**：整个 TCP/IP 栈、拥塞控制、分片重组、DNS、TLS、socket 缓冲调优。
- **难点**：无——消费面只有 8 个端点、请求/响应一问一答，消息化最自然。

### 2.6 内核内存分配 → loomos 物理页分配器 + 固定预算
- **OS 提供**：按需分页、swap、页缓存、OOM killer、mmap 文件映射。
- **loomos 实际用**：普通堆分配（无 mmap 直接调用）；**内存预算语义已有**（MemoryLimit/CpuBudget）。
- **自实现最小形态**：物理页分配器 + 每组件 `MemoryLimit` **编译期/装配期固定**
  （Desired/Applied 已有）——不允许运行时超卖，OOM 在准入时拒绝而非事后 kill。
- **砍掉**：swap、按需分页（demand paging）、页缓存、mmap 文件映射、OOM killer 随机性。
- **难点**：Rust 分配器接入（GlobalAlloc → 页分配器，常规工作）。

### 2.7 帧缓冲/设备 mmap（未来板载路径）→ loomos 帧租约（**已有雏形**）
- **OS 提供**：udmabuf（现用）、dma-buf fence、V4L2。
- **loomos 实际用**：Buffer typestate + 单 Owner + 隔离区 = **用户态 dma-buf 语义的删减版已写好**。
- **自实现最小形态**：物理连续帧池 + frame_lease（旧板 frame_lease.h 的 Rust 化）+
  Cache sync 两个显式操作（`SyncForDevice/SyncForCpu` 已在 typestate 里）。
- **砍掉**：dma-buf 多消费者、fence 上下文、动态缓冲区大小。
- **难点**：无——这是全项目**离自实现最近的一块**（03 文档 A3 的镜像面）。

### 2.8 进程监督 → loomos Supervisor（**自实现已完成**）
- **OS 提供**：systemd（Restart/backoff/WatchdogSec/MemoryMax）、信号（SIGKILL/SIGSTOP）。
- **loomos 实际用**：**零 systemd 依赖**（loomosd 单进程内组件监督已实现：四类故障×三级恢复、
  重启风暴熔断）；旧板 systemd 假闸门教训已吸收（11 §11.3.2）。
- **自实现形态**：**就是现在的 Supervisor**——记录结论：这一项已经删减完成，
  原生形态只差"跨进程"版本（组件独立进程时需要 IPC 化监督，暂不需要）。
- **难点**：无。

### 2.9 随机数 → 计时器抖动 + 硬件 RNG 寄存器
- **现状**：原型刻意去掉了 getrandom 依赖（windows-gnu dlltool 事故），全确定性种子。
- **自实现**：frame_token/uuid 类需求读 SoC RNG 寄存器或计时器抖动池；熵要求极低
  （token 非安全凭据）。
- **砍掉**：getrandom 全 API、熵池管理。

## 3. 删减总表（Linux 提供 vs loomos 需要）

| Linux 能力 | loomos 需要 | 删减后 | 对应自实现载体 |
|---|---|---|---|
| ~300+ syscall | **≤15 族** | 单页内核态入口表 | 原生内核入口表 |
| CFS + DEADLINE + cgroup | 静态优先级 + DEADLINE 子集 | 三参数预算 | CpuBudget（已定义） |
| ext4 + VFS | 追加日志 + 扁平 namespace | 无目录树/无页缓存 | ConfigNamespace + EventLog（已有） |
| TCP/IP 全栈 | loopback HTTP | 消息端点 | mini_http + 端点（HTTP 已自实现） |
| futex 家族 | WAIT/WAKE | 双阶段锁 | std::sync 语义照抄 |
| udmabuf + fence | 帧租约 + cache sync | 固定帧池 | Buffer typestate + frame_lease（已有） |
| systemd | 组件监督 | 进程内 Supervisor | Supervisor（已完成） |
| getrandom | 低熵 token | RNG 寄存器 | 计时抖动池 |
| mmap 按需分页 + swap | 固定预算物理页 | 准入时拒绝 | MemoryLimit（已定义） |

## 4. 明确**不做**的自实现（防范围扩大）

1. **POSIX 兼容层**：loomos 组件全是 Rust 源码级组件，不需要二进制兼容；
   外部程序接入走 DeviceProvider/HTTP 适配器（已支持）。
2. **动态链接/加载器**：静态链接即可。
3. **多用户 uid/gid**：capability 模型替代（已经实现）。
4. **通用网络栈**：只保留线上协议层（HTTP 解析器已自实现），传输层消息化。
5. **Swap/按需分页**：固定预算准入（这正是「拒绝而非事后 kill」的架构原则）。
6. **图形/输入栈**：HMI 是独立域（platforms 文档的 HMI SOP 与本内核无关）。

## 5. 路线衔接

- **宿主阶段（现在）**：本文只是地图；代码零改动。stdlib → syscall 的映射表
  建议在 Linux Backend（`platform/linux` feature）实现 B 类项时**顺手落成常量表**
  （每项依赖：crate 调用点 → syscall → 是否必须）。
- **原生阶段（远期，P7/P8 判据触发才启动）**：按本文 §2 的顺序实现——
  先 2.7 帧租约与 2.8 Supervisor（已有雏形），再 2.4/2.5（日志与端点），
  调度器与内存分配器最后（风险最大）。
- **一个重要观察**：loomos 的用户态抽象当年就是**参照 OS 语义设计的**
  （LeaseManager≈租约、CapabilityStore≈capability、ConfigService≈扁平文件系统、
  Supervisor≈systemd、EventLog≈journald、mini_http≈socket 层之上）。
  所以"删减成自实现"的大半工作不是新写，而是**给已有抽象去掉 Linux 假设**。
